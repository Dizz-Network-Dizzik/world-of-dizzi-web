Was es zusammenhält

Drei Entscheidungen, alles Weitere folgt

Lokal-first

Der Core läuft offline. Cloud-Dienste sind zuschaltbare Konnektoren — jederzeit abschaltbar, immer als externer Schritt sichtbar. Das macht Synchronisation schwerer; ich habe mich bewusst dafür entschieden, weil die Daten auf die Maschine gehören, die sie erzeugt hat.

Vertrags-getrieben

Ein geschriebener App-Vertrag, zehn Apps, die auf ihn hin gebaut sind. Eine App, die ihn beantwortet, erscheint von selbst im Dashboard und ist für die KI ansprechbar — niemand verdrahtet sie von Hand.

Ehrlich per Gesetz

Ehrlichkeit ist hier kein Tonfall, sondern eine geschriebene Regel, an die sich der Code halten muss: ein nicht gemessener Wert wird als „nicht gemessen“ ausgegeben, nie als Null. Dieselbe Regel gilt für diese Website.

Die Methode

Gesetze vor Code

Ein System dieser Größe ist für eine Person nicht baubar ohne Regeln, die auch dann tragen, wenn niemand hinsieht. Sie stehen geschrieben im Repository, und sie sind älter als der meiste Code: Gesetze vor Code, Verträge vor Funktionen, Recherche vor Entscheidungen.

Ein Mensch führt Regie. Ein verwaltender Chat hält den Gesamtstand und entscheidet, was als Nächstes passiert; getrennte Bau-Chats erledigen die Arbeit, ein Arbeitspaket nach dem anderen. Sie sprechen nicht miteinander; sie verständigen sich ausschließlich über geschriebene Übergabe-Dokumente. Und alles Unumkehrbare — Geld, Veröffentlichen, Löschen — steht hinter einem menschlichen Gate.

Die Arbeitsweise

Der Weg eines Arbeitspakets

Sechs Stationen zwischen der ersten geschriebenen Zeile und dem Merge. Jede davon ist eine Regel mit einem Dokument dahinter — keine Beschreibung, die hinterher entstanden ist.

  1. Der Auftrag steht vor der Arbeit

    Ein Paket beginnt als Datei: Ziel, Ausgangs-Commit, verbotene Züge und das Gate, das es bestehen muss. Geschrieben für jemanden ohne Erinnerung an gestern — denn genau der übernimmt es.

  2. Die Spur steht im Dokument

    Unabhängige Pakete laufen gleichzeitig, jedes in einem eigenen Arbeitsbaum auf einem eigenen Zweig; zwei Bauten bearbeiten nie dieselbe Arbeitskopie. Nachprüfbar statt behauptet: Die Verträge im Repository nennen Baum, Zweig und Stufe in ihrem Kopf.

  3. Die Freigabe kommt vor der Nacht

    Ein unbeaufsichtigter Lauf trägt seine Freigaben schriftlich: was neu gestartet werden darf, was grün bleiben muss, was er nicht anfassen darf. Erst wird der Plan einmal zurückgelesen, dann bestätigt ein Mensch, dann arbeitet die Maschine allein durch.

  4. Zweimal sauber hintereinander

    Der Abschlussblock ist eine Schleife, kein Häkchen: prüfen, durchsehen, beheben, alles noch einmal prüfen — fertig ist erst nach zwei sauberen Durchläufen in Folge. Ein einzelner grüner Lauf sieht genauso aus wie eine Prüfung, die ihr Prüfobjekt nie erreicht hat.

  5. Es endet in einem Dokument

    Das Letzte, was ein Paket erzeugt, ist ein Übergabe-Blatt: gebaut, gemessen, offen geblieben. Der nächste Chat startet beim Blatt. Eine Übergabe, die nur im Gespräch lebt, ist mit dem Gespräch verloren.

  6. Der Überblick bleibt beim Menschen

    Nach einem großen Paket verlangen die Regeln eine große Kontrollrunde über alles — und davor eine systematische Ausgabe dessen, was die Systeme jetzt tun. Der Überblick wird an den Teilen gelesen, nicht einer Zusammenfassung geglaubt.

Diese Website ist nach denselben Regeln entstanden: erst aufgeschrieben, in einem eigenen Arbeitsbaum gebaut, an einem Gate aus benannten Skripten gemessen — und nicht eher fertig, als bis dieses Gate zweimal hintereinander sauber war.
